Communication and file integrations

Klyo includes real provider adapters. Connecting them requires an account and credentials from each provider. Klyo does not create third-party subscriptions or purchase API credits. No credentials are needed for the rest of the CRM. Never paste secrets into chat or a support ticket.

Microsoft 365 inbox

Choose Work or school Microsoft 365 or Personal Outlook.com / Hotmail before Microsoft sign-in. The work option requires your actual organization account. The personal option requires an Outlook mailbox; using a Gmail address to sign in to Microsoft does not connect Gmail mail.

For personal Outlook, the operator must set the existing Entra application's Authentication → Supported account types to Accounts in any organizational directory and personal Microsoft accounts. Keep all existing Web callback URIs and the organizational tenant setting. Klyo selects the account-specific authority. Personal connections request only Mail.Read and offline access, without shared-mailbox access.

Use the same Microsoft Entra application configured for SharePoint, but add a Web redirect URI:

https://klyolabs.com/api/communications/oauth/microsoft_mail/callback

Keep the existing SharePoint redirect URI. Set MICROSOFT_CLIENT_ID, MICROSOFT_CLIENT_SECRET, and optionally MICROSOFT_TENANT_ID in Railway. The default tenant is organizations. Add Microsoft Graph delegated permissions Mail.Read and Mail.Read.Shared. Offline access allows refresh tokens. Your organization's policy may require administrator consent. No Mail.Send scope is requested and no follow-up messages are sent.

For an info@ or other shared mailbox, first give the signed-in Microsoft user delegated read access to that mailbox in Microsoft 365. Connect or reconnect Microsoft 365 in Klyo to consent to Mail.Read.Shared, then choose Shared mailbox next to the connection and enter its email address. Klyo verifies access to that inbox before saving a separate connection. This does not grant Microsoft mailbox permissions or impersonate arbitrary mailboxes. Your own inbox remains connected separately. Each connection can have its own folders, synchronization and RFQ rules, with the same CRM privacy rules as below. Revoking Microsoft access stops synchronization; reconnect if consent or delegated access changes. Account-specific behavior must be tested with your own tenant.

In Inbox → Connect Microsoft 365, review the privacy notice and sign in. Each user's inbox is private to that user, within the active Team or Personal space. Incoming messages whose sender email matches an existing CRM contact are linked to that contact and its company. Linking an email to a deal also links it to the deal's contact/company. Linked correspondence is visible to workspace colleagues with access to those records. Unmatched and unlinked messages remain private. Do not connect a mailbox containing correspondence you are not authorized to publish to CRM records.

Sync runs roughly once per minute while the server is running. Sync now starts it immediately. The first sync imports the inbox in batches; later syncs use Microsoft delta cursors. Deleted Outlook messages are marked as removed in the CRM. Disconnecting removes imported messages from that connection; associated CRM deals/tasks remain. Tokens are encrypted in the database and never exposed to the browser. Attachments are loaded on demand from Microsoft; downloads are limited to 20 MB and follow the same message access rules. Message bodies are displayed as plain text, never executable email HTML.

RFQ register

Only the Team owner (or Personal owner) can configure inbound rules. Connect the mailbox, then open RFQ register → Inbound rules. Choose the mail folder, optional subject fragment and sender domain, assignee, pipeline/stage and SLA in minutes. Saving activates the rule for future incoming messages only. Each matching message creates at most one request, opportunity and response task. The request shows an exact deadline and live remaining/overdue time. Mark responded manually to stop its timer; this does not send an email. Remove the rule to stop new requests. Rules cannot assign people or pipelines from a different workspace. Folders can be routed using Outlook's own mail rules; Klyo does not alter your mailbox's rules.

Google Drive

In Google Cloud Console enable Google Drive API, configure the OAuth consent screen, create a Web application OAuth client and add:

https://klyolabs.com/api/communications/oauth/google_drive/callback

Set GOOGLE_CLIENT_ID and GOOGLE_CLIENT_SECRET in Railway (the same variables used for existing Google sign-in/Gmail sending). Preserve their existing redirect URIs. Configure publishing/test-user restrictions and complete Google verification where required. Drive requests delegated https://www.googleapis.com/auth/drive to browse existing folders and manage files; consent covers the account's Drive, while Klyo confines CRM actions to the selected folder after connection. Use a dedicated account/folder if appropriate.

Open Files → Google Drive → Connect, grant access, then Choose CRM folder. Users can browse subfolders, link an existing file to a CRM record, upload new files and download linked files. Workspace users share this connection; only the owner can configure/disconnect it. Personal uses a separate connection. Upload/download limit is 20 MB per file. Google-native Docs/Sheets should be exported to PDF/XLSX in Drive before downloading through Klyo; this integration transfers ordinary files, not Google editor documents. Files in shared drives are supported where the connected account and Google policy permit access. Removing a CRM link does not delete its cloud file.

Dropbox

Create an OAuth app at the Dropbox App Console. Choose Scoped access, Full Dropbox if you need to choose existing folders, and enable files.metadata.read, files.content.read, files.content.write. App-folder apps can only see their app folder. Add this redirect URI:

https://klyolabs.com/api/communications/oauth/dropbox/callback

Set DROPBOX_CLIENT_ID (app key) and DROPBOX_CLIENT_SECRET in Railway. Keep secrets server-side. Production distribution may require Dropbox review. Connect under Files → Dropbox, choose a CRM folder and use the same link/upload/download workflow as Drive. The same 20 MB limit and owner/Team/Personal rules apply. Dropbox chooses a new name if an upload would conflict with an existing file. Original cloud files remain when a CRM link is removed or the connection is disconnected.

Apollo.io

An Apollo subscription/API key with the required endpoint permissions is required. In Contacts → Apollo.io import, the workspace owner enters the API key (stored encrypted). Search people by title, company domain or keywords. Results may contain obfuscated names; selecting up to ten people and confirming Apollo credit usage calls bulk enrichment. Only results with a usable email are imported, existing emails are reused and repeated Apollo IDs do not create duplicate contacts. Company names are matched within the active workspace. No emails are sent and phone/personal-email reveal is disabled. Apollo's own API pricing/credit limits apply. Importing contacts still respects the CRM subscription's contact limit. The key is never returned to the browser after saving it.

Parcel tracking

Order → Shipment status can fetch real DHL status scans, estimated delivery and tracking events through DHL's Tracking Unified API. Obtain an approved subscription key for that API in the DHL Developer Portal. The workspace owner enters it in Shipment status → DHL API key → Connect DHL. The key is encrypted and is never returned to the browser. No API subscription or credits are purchased by Klyo. A demo key returns example data and must not be used for actual customer deliveries.

Set the order carrier to DHL and enter the tracking number, then choose Refresh DHL status. Results are cached for five minutes; requests are spaced for the workspace and provider rate limits are respected. The API subscription must cover the shipment and applicable DHL division. A carrier delivery scan does not set the customer's signed acknowledgment, invoice or payment. Disconnect removes the key; the last downloaded order snapshot remains historical data. Changing the carrier or number clears that snapshot.

UPS, FedEx, DPD and InPost remain available through fixed official tracking pages using Open carrier tracking. Live API adapters for those carriers are not included. Connecting DHL does not imply support for their APIs. You can continue opening the official tracking page for DHL as well.

Fakturownia invoices and payment status

Under an order's Invoice provider button, the workspace owner can configure a Fakturownia account subdomain and API token. Only https://<subdomain>.fakturownia.pl is accepted. The token is encrypted. Preview the customer invoice: buyer, tax ID, issue/payment dates, currency, tax rate, original quantities and net line totals. Per-item discounts are included, and any negotiated final order amount is distributed proportionally across items with exact cent rounding. Tax is added separately; the sum of invoice net line totals must match the reviewed order net amount. If the order changes after preview, Klyo requires a new preview. Issuance reserves and locks the financial order details to prevent duplicate or conflicting invoices. Explicitly authorize issuance to create the invoice in Fakturownia; Klyo does not email it or send payment requests automatically. The provider's own configuration controls tax/compliance/numbering. Review that configuration before issuing real documents.

The invoice is assigned external ID klyo-<workspace>-<order>. An order can issue only once. If a network failure makes the outcome uncertain, Klyo reserves the order and requires reconciliation: check Fakturownia for that external ID, enter the provider invoice ID and reconnect it. Do not create a second invoice to resolve an interrupted request. Refresh invoice and payment status fetches the provider's status; no bank account is connected by Klyo. Check the provider's actual payment records and resolve mismatched currencies/amounts before treating an order as settled. The provider response preserves its actual gross paid amount. The CRM order ledger uses net item amounts, so partial payment is allocated proportionally as order net total × provider paid / invoice gross total; a fully paid invoice settles the order net amount. Klyo does not implement KSeF or tax filing itself.

Deployment and secrets

Set APP_URL=https://klyolabs.com. Set one long, random, stable INTEGRATION_ENCRYPTION_KEY in Railway before connecting providers. If omitted, token encryption derives from JWT_SECRET; changing the encryption secret invalidates existing saved tokens and requires reconnecting providers. Never rotate it without planning reconnections. Configure exact HTTPS callback URLs, never browser-side client secrets. Restart/redeploy after changing environment variables. The connection UI shows whether server configuration is missing; it does not simulate a successful connection.

Provider failures/rate limits stop or defer synchronization and show an error. Credentials, email bodies and access tokens are not written to team audit logs. Team/Personal data and mailbox ownership are checked by the backend on every request. Test with a dedicated mailbox and sandbox provider account before inviting the team. This release was tested using isolated local databases and mocked provider responses; live sign-in and account-specific permissions require your credentials.

Integracje poczty i plików

Klyo ma adaptery dostawców. Połączenie wymaga własnego konta i danych dostawcy. Klyo nie zakłada subskrypcji ani nie kupuje kredytów API. Pozostałe funkcje CRM nie wymagają tych danych. Nie przesyłaj sekretów przez czat ani zgłoszenia do pomocy.

Skrzynka Microsoft 365

Przed logowaniem wybierz Służbowe lub szkolne Microsoft 365 albo Osobiste Outlook.com / Hotmail. Dla konta służbowego podaj właściwy adres organizacji. Konto osobiste musi mieć skrzynkę Outlook; logowanie do Microsoft adresem Gmail nie podłącza poczty Gmail.

Aby włączyć osobisty Outlook, operator wybiera w istniejącej aplikacji Entra: Authentication → Supported account types → Accounts in any organizational directory and personal Microsoft accounts. Zachowaj wszystkie adresy powrotu Web i ustawienie dzierżawy organizacji. Klyo wybiera właściwą ścieżkę dla danego konta. Osobiste połączenie prosi tylko o Mail.Read i dostęp offline, bez dostępu do skrzynek współdzielonych.

Użyj aplikacji Microsoft Entra przygotowanej dla SharePoint i dodaj adres przekierowania typu Web:

https://klyolabs.com/api/communications/oauth/microsoft_mail/callback

Zachowaj istniejący adres SharePoint. W Railway ustaw MICROSOFT_CLIENT_ID, MICROSOFT_CLIENT_SECRET oraz opcjonalnie MICROSOFT_TENANT_ID; domyślna dzierżawa to organizations. Dodaj delegowane uprawnienia Graph Mail.Read i Mail.Read.Shared. Dostęp offline umożliwia odświeżanie tokenów. Polityka organizacji może wymagać zgody administratora. Integracja nie prosi o Mail.Send i nie wysyła automatycznych wiadomości przypominających klientom.

Dla skrzynki współdzielonej, np. info@, najpierw nadaj zalogowanej osobie delegowany dostęp do jej odczytu w Microsoft 365. Połącz lub ponownie połącz konto w Klyo i zaakceptuj Mail.Read.Shared. Następnie wybierz Skrzynka współdzielona przy połączeniu i podaj adres. Klyo sprawdza dostęp przed zapisaniem osobnego połączenia. Nie nadaje uprawnień Microsoft ani nie podszywa się pod dowolną skrzynkę. Własna skrzynka pozostaje połączona osobno. Każde połączenie ma własne foldery, synchronizację i reguły zapytań. Cofnięcie uprawnień zatrzymuje synchronizację; po zmianie zgody lub delegacji połącz ponownie. Zachowanie trzeba sprawdzić we własnej organizacji.

Otwórz Skrzynka odbiorcza → Połącz Microsoft 365, przeczytaj informację o prywatności i zaloguj się. Skrzynka jest prywatna dla użytkownika w aktywnej przestrzeni zespołowej lub prywatnej. Wiadomości od adresów pasujących do istniejących kontaktów CRM są przypisywane do kontaktu i firmy. Powiązanie wiadomości ze sprawą łączy ją również z kontaktem i firmą sprawy. Powiązana korespondencja jest widoczna dla współpracowników mających dostęp do rekordów. Niedopasowane i niepowiązane wiadomości pozostają prywatne. Nie łącz skrzynki z korespondencją, której nie możesz udostępniać w CRM.

Synchronizacja działa mniej więcej co minutę podczas pracy serwera. Synchronizuj teraz uruchamia ją od razu. Pierwszy odczyt importuje skrzynkę partiami, kolejne korzystają z kursorów zmian Microsoft. Wiadomości usunięte w Outlooku są oznaczane jako usunięte w CRM. Odłączenie usuwa zaimportowane wiadomości danego połączenia; sprawy i zadania CRM pozostają. Tokeny są szyfrowane w bazie i niewidoczne dla przeglądarki. Załączniki są pobierane na żądanie, do 20 MB, według tych samych zasad dostępu. Treść wiadomości jest wyświetlana jako zwykły tekst, a nie wykonywalny HTML.

Rejestr zapytań ofertowych

Reguły nowych zapytań ustawia tylko właściciel zespołu lub przestrzeni prywatnej. Połącz skrzynkę i otwórz Rejestr zapytań → Reguły przychodzące. Wybierz folder, opcjonalny fragment tematu i domenę nadawcy, osobę odpowiedzialną, lejek, etap oraz czas odpowiedzi w minutach. Zapis uruchamia regułę wyłącznie dla przyszłych wiadomości. Każda pasująca wiadomość tworzy najwyżej jedno zapytanie, szansę i zadanie odpowiedzi. Zapytanie pokazuje dokładny termin i pozostały lub przekroczony czas. Ręcznie oznacz odpowiedź, aby zatrzymać licznik; nie wysyła to wiadomości. Usunięcie reguły zatrzymuje nowe zapytania. Osoby i lejki muszą należeć do tej samej przestrzeni. Możesz kierować pocztę do folderów regułami Outlooka; Klyo ich nie zmienia.

Google Drive

W Google Cloud Console włącz Google Drive API, skonfiguruj ekran zgody OAuth i klienta typu aplikacja internetowa. Dodaj:

https://klyolabs.com/api/communications/oauth/google_drive/callback

W Railway ustaw GOOGLE_CLIENT_ID i GOOGLE_CLIENT_SECRET — te same, których używa logowanie Google i wysyłka Gmail. Zachowaj wcześniejsze adresy przekierowania. Skonfiguruj publikację, użytkowników testowych i wymaganą weryfikację Google. Obecny zakres https://www.googleapis.com/auth/drive obejmuje przeglądanie istniejących folderów i zarządzanie plikami całego połączonego konta. Po wybraniu folderu Klyo ogranicza operacje CRM do tego folderu i podfolderów. W razie potrzeby użyj dedykowanego konta lub folderu.

Otwórz Pliki → Google Drive → Połącz, zaakceptuj uprawnienia i wybierz Wybierz folder CRM. Użytkownicy mogą przeglądać podfoldery, podłączać istniejące pliki do rekordów, wgrywać i pobierać dokumenty. Połączenie jest współdzielone w przestrzeni; konfiguruje je i odłącza wyłącznie właściciel. Przestrzeń prywatna ma osobne połączenie. Limit wgrania i pobrania to 20 MB na plik. Dokumenty i arkusze Google wyeksportuj w Drive do PDF/XLSX przed pobraniem przez Klyo — integracja przesyła zwykłe pliki, a nie dokumenty edytorów Google. Dyski współdzielone działają w granicach dostępu konta i polityk Google. Usunięcie powiązania CRM nie usuwa pliku z chmury.

Dropbox

Utwórz aplikację OAuth w Dropbox App Console. Wybierz Scoped access i Full Dropbox, jeśli chcesz wybierać istniejące foldery. Włącz files.metadata.read, files.content.read i files.content.write. Typ App folder widzi wyłącznie własny folder aplikacji. Dodaj:

https://klyolabs.com/api/communications/oauth/dropbox/callback

W Railway ustaw DROPBOX_CLIENT_ID jako klucz aplikacji i DROPBOX_CLIENT_SECRET jako sekret. Dane pozostają po stronie serwera. Udostępnienie produkcyjne może wymagać oceny Dropbox. Połącz w Pliki → Dropbox, wybierz folder CRM i używaj podłączania, wgrywania i pobierania jak w Drive. Obowiązuje limit 20 MB i te same zasady właściciela oraz przestrzeni. Dropbox wybiera nową nazwę przy konflikcie plików. Oryginały pozostają po odłączeniu integracji lub usunięciu powiązania.

Apollo.io

Potrzebujesz subskrypcji i klucza Apollo z dostępem do odpowiednich metod API. Właściciel wpisuje klucz w Kontakty → Import Apollo.io; zapis jest szyfrowany. Szukaj osób po stanowisku, domenie firmy lub słowach kluczowych. Wyniki mogą mieć częściowo ukryte nazwiska. Zaznaczenie do dziesięciu osób i potwierdzenie wykorzystania kredytów uruchamia zbiorcze uzupełnienie danych. Importowane są tylko osoby z użytecznym adresem e-mail. Istniejące adresy są używane ponownie, a powtórzony identyfikator Apollo nie tworzy duplikatu. Firmy są dopasowywane w aktywnej przestrzeni. Nie wysyłamy wiadomości; odkrywanie telefonów i prywatnych adresów jest wyłączone. Obowiązują cennik i limity kredytów Apollo oraz limit kontaktów planu Klyo. Po zapisaniu klucz nie jest zwracany do przeglądarki.

Śledzenie przesyłek

Zamówienie → Status przesyłki może pobierać rzeczywiste skany DHL, przewidywaną dostawę i zdarzenia przez DHL Tracking Unified API. Uzyskaj zatwierdzony klucz tej usługi w portalu DHL. Właściciel wpisuje go w Status przesyłki → Klucz API DHL → Połącz DHL. Klucz jest szyfrowany i nie jest zwracany do przeglądarki. Klyo nie kupuje abonamentu ani kredytów. Klucz demonstracyjny zwraca przykładowe dane i nie służy do dostaw klientów.

W zamówieniu wybierz DHL, podaj numer przesyłki i kliknij Odśwież status DHL. Wynik jest buforowany przez pięć minut, a odstępy zapytań i limity dostawcy są respektowane. Subskrypcja API musi obejmować przesyłkę i właściwy oddział DHL. Skan doręczenia nie oznacza podpisanego odbioru, wystawienia faktury ani płatności. Odłączenie usuwa klucz, ale ostatni zapis statusu pozostaje historyczny. Zmiana numeru lub przewoźnika czyści ten zapis.

UPS, FedEx, DPD i InPost mają przycisk Otwórz śledzenie przewoźnika, kierujący na oficjalną stronę. Adaptery ich API nie są częścią tej wersji. Połączenie DHL nie włącza ich API. Dla DHL również można otworzyć oficjalną stronę.

Fakturownia — faktury i płatności

W zamówieniu właściciel otwiera Dostawca faktur i ustawia subdomenę konta oraz token Fakturowni. Akceptowane są tylko adresy https://<subdomena>.fakturownia.pl. Token jest szyfrowany. Sprawdź podgląd faktury: nabywcę, NIP, datę wystawienia i płatności, walutę, podatek, oryginalne ilości i kwoty netto pozycji. Rabaty pozycji są uwzględniane, a uzgodniona końcowa kwota zamówienia jest rozdzielana proporcjonalnie z dokładnością do grosza. Podatek jest doliczany oddzielnie. Suma netto musi odpowiadać sprawdzonej kwocie netto zamówienia. Zmiana zamówienia wymaga ponownego podglądu.

Wystawianie rezerwuje operację i blokuje dane finansowe, aby uniknąć duplikatów i konfliktów. Jawnie zatwierdź wystawienie, aby utworzyć fakturę w Fakturowni. Klyo nie wysyła jej automatycznie e-mailem ani nie wysyła wezwania do zapłaty. Numery, podatki i zgodność określa konfiguracja dostawcy — sprawdź ją przed wystawianiem dokumentów. Faktura otrzymuje zewnętrzny identyfikator klyo-<przestrzeń>-<zamówienie>. Zamówienie można zafakturować jeden raz.

Jeśli awaria sieci pozostawi niepewny wynik, Klyo zachowa rezerwację i zażąda uzgodnienia. Sprawdź identyfikator zewnętrzny w Fakturowni, wpisz ID znalezionej faktury i powiąż ją. Nie wystawiaj drugiej faktury, aby naprawić przerwane żądanie. Odśwież fakturę i płatności pobiera status dostawcy; Klyo nie łączy rachunku bankowego. Sprawdź rzeczywiste wpłaty oraz zgodność kwot i walut. Odpowiedź dostawcy zachowuje faktyczną wpłatę brutto. Rejestr zamówienia używa netto: częściowa wpłata jest rozdzielana jako netto zamówienia × wpłacone brutto / brutto faktury, a pełna zapłata rozlicza całe netto. Klyo nie realizuje KSeF ani deklaracji podatkowych.

Wdrożenie i sekrety

Ustaw APP_URL=https://klyolabs.com i długi, losowy, stabilny INTEGRATION_ENCRYPTION_KEY w Railway przed łączeniem dostawców. Bez niego szyfrowanie korzysta z JWT_SECRET. Zmiana klucza unieważnia zapisane tokeny i wymaga ponownego połączenia, więc zaplanuj ją wcześniej. Adresy powrotne muszą być dokładnymi adresami HTTPS. Sekrety nigdy nie trafiają do frontendu. Po zmianie zmiennych zrestartuj lub wdróż usługę. Ekran połączeń pokazuje brak konfiguracji i nie symuluje sukcesu.

Błędy i limity dostawcy zatrzymują lub opóźniają synchronizację i pokazują komunikat. Sekrety, treści wiadomości i tokeny nie są zapisywane w dzienniku zespołu. Przestrzeń i własność skrzynki są sprawdzane na serwerze przy każdym żądaniu. Przed zaproszeniem zespołu użyj dedykowanej skrzynki i konta testowego dostawcy. Testy automatyczne opierają się na odizolowanych bazach i symulowanych odpowiedziach; rzeczywiste logowanie i uprawnienia wymagają Twojego konta.
