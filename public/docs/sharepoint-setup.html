Klyo — SharePoint setup

The integration is implemented in Klyo. To connect it, the Klyo owner must register a Microsoft Entra application and add its credentials in Railway. The Files tab alone does not mean Microsoft is connected.

1. Register an application

  1. Sign into Microsoft Entra admin center with a work account that can administer your Microsoft 365 organization.
  2. Open Identity → Applications → App registrations → New registration.
  3. Name: Klyo CRM.
  4. For multiple customer organizations choose Accounts in any organizational directory. For your own organization only, select a single tenant and provide its identifier.
  5. Redirect platform: Web. Exact production URL: https://klyolabs.com/api/sharepoint/callback.
  6. Save the Application (client) ID and, for a single organization, the Directory (tenant) ID.

2. Permissions and secret

Under API permissions → Add a permission → Microsoft Graph → Delegated permissions, add Files.ReadWrite for files within the signed-in user's access, Sites.Read.All for finding sites and choosing a library, and offline_access for token refresh.

Do not add Application permissions or Sites.ReadWrite.All. Your Microsoft 365 policy may require administrator approval. Site-read access is broad; Klyo additionally confines CRM file browsing and writes to the folder selected by the owner.

Under Certificates & secrets → New client secret, create a secret. Save its Value directly in a password manager or Railway. The secret ID is not its value. Never paste the secret into chat or commit it. Record its expiry and replace it before expiration.

3. Railway variables

In the Klyo service's Variables, set MICROSOFT_CLIENT_ID to the application ID and MICROSOFT_CLIENT_SECRET to the secret value. Use MICROSOFT_TENANT_ID=organizations for multiple organizations or the tenant ID for one organization. Set MICROSOFT_REDIRECT_URI=https://klyolabs.com/api/sharepoint/callback.

Set a stable, random, server-only INTEGRATION_ENCRYPTION_KEY containing at least 32 random bytes. APP_URL must be https://klyolabs.com. Apply changes and wait for deployment. Never put secrets in frontend files. Do not change the encryption key without planning to reconnect all integrations. If no integration key is set, encryption derives from JWT_SECRET; changing it likewise requires reconnecting.

4. Connect a workspace

  1. As team owner, open Team → Files → Configure SharePoint. Personal has its own separate private connection.
  2. Choose Connect Microsoft, sign in and review consent.
  3. Find the site, select its library and choose a folder, preferably a dedicated Klyo CRM folder.
  4. Choose Use this folder for CRM files.
  5. Upload and open a sample file, then link it to a contact or quote.

Team editors can add and link files; viewers can read them. Only the owner can change the connection and root folder. Opening the original Microsoft link still requires the user's Microsoft permissions. The CRM shares SharePoint access through the owner's connected account, so choose a folder intended for the workspace.

Supported workflows

  • Manual chunked uploads up to 250 MB, with progress and retry of failed chunks.
  • Link existing documents within the selected folder and its descendants to contacts, companies, deals, products or quotes.
  • Import CSV/XLSX price lists up to 10 MB from SharePoint, with preview and explicit approval.
  • Separate Team and Personal connections and document lists.
  • Unlink removes the CRM link, not the cloud file. Disconnect retains cloud files and CRM metadata, blocking access until the correct folder is connected again.

Transferring team ownership disconnects the integration. The new owner connects their Microsoft account and selects a folder. Files remain in SharePoint. Uploaded names receive a short random suffix to avoid overwriting documents.

Changing folders interrupts pending uploads. Closing the upload window stops after the current chunk; transfers do not resume after a page reload. Incomplete upload sessions expire at Microsoft. Library and Microsoft account limits still apply. There is no background file synchronization or automatic messaging.

Troubleshooting

  • Microsoft sign-in has not been configured: check MICROSOFT_CLIENT_ID, MICROSOFT_CLIENT_SECRET and the Railway deployment.
  • Redirect URI mismatch: the Entra Web URL must exactly match MICROSOFT_REDIRECT_URI, including HTTPS and path.
  • Need admin approval / missing sites: the Microsoft administrator must approve permissions and grant access to the site.
  • Reconnect your Microsoft account: authorization expired or was revoked. Reconnect and select the folder again.
  • This item is outside the connected CRM folder: select a document within that folder or a descendant.

Microsoft documentation: application registration, authorization-code flow, upload sessions and site search.

Klyo — konfiguracja SharePoint

Integracja jest przygotowana w aplikacji. Do pierwszego połączenia właściciel Klyo musi zarejestrować aplikację Microsoft Entra i dodać jej dane w Railway. Sama obecność zakładki Files nie oznacza aktywnego połączenia z Microsoft.

1. Zarejestruj aplikację

1. Zaloguj się do Microsoft Entra admin center kontem służbowym z dostępem do swojej organizacji Microsoft 365.

2. Otwórz Identity → Applications → App registrations → New registration.

3. Nazwa: Klyo CRM.

4. Dla Klyo obsługującego różne firmy wybierz Accounts in any organizational directory. Jeśli wdrożenie ma obsługiwać wyłącznie Twoją firmę, możesz wybrać jeden tenant i podać jego identyfikator w konfiguracji.

5. Platforma przekierowania: Web. Dokładny adres produkcyjny:

https://klyolabs.com/api/sharepoint/callback

6. Zapisz Application (client) ID. Dla konfiguracji jednej organizacji zapisz też Directory (tenant) ID.

2. Ustaw uprawnienia i sekret

W API permissions → Add a permission → Microsoft Graph → Delegated permissions dodaj:

- Files.ReadWrite — odczyt oraz zapisywanie plików w zakresie uprawnień zalogowanego użytkownika.

- Sites.Read.All — wyszukiwanie witryn i wybór biblioteki SharePoint.

- offline_access — odświeżanie połączenia bez logowania przy każdym pliku.

Nie dodawaj uprawnień typu Application ani Sites.ReadWrite.All. Administrator Microsoft 365 może wymagać zatwierdzenia dostępu zgodnie z polityką swojej organizacji. Zakres odczytu witryn jest szeroki; Klyo dodatkowo ogranicza przeglądanie i zapisy z CRM do folderu wybranego przez właściciela.

W Certificates & secrets → New client secret utwórz sekret, zapisz jego Wartość bezpośrednio do menedżera haseł lub Railway. Nie używaj identyfikatora sekretu zamiast jego wartości. Nie przesyłaj sekretu przez czat ani nie dodawaj do repozytorium. Zanotuj datę wygaśnięcia i wymień sekret przed tym terminem.

3. Dodaj zmienne w Railway

Otwórz usługę Klyo → Variables. Dodaj:

Zmienna Wartość
MICROSOFT_CLIENT_ID Application (client) ID
MICROSOFT_CLIENT_SECRET Wartość utworzonego sekretu
MICROSOFT_TENANT_ID organizations dla wielu firm albo Directory (tenant) ID dla jednej firmy
MICROSOFT_REDIRECT_URI https://klyolabs.com/api/sharepoint/callback
INTEGRATION_ENCRYPTION_KEY Nowa, losowa, długa wartość przechowywana jako sekret; minimum 32 losowe bajty

Sprawdź istniejącą APP_URL: musi wskazywać https://klyolabs.com. Zastosuj zmiany i poczekaj na zakończenie wdrożenia. Sekret oraz klucz szyfrowania działają wyłącznie na serwerze. Nie dodawaj ich do plików frontendu.

Nie zmieniaj klucza szyfrowania bez ponownego połączenia wszystkich integracji. Gdy INTEGRATION_ENCRYPTION_KEY nie jest ustawiony, aplikacja korzysta z JWT_SECRET; jego zmiana również wymaga ponownego połączenia.

4. Połącz konkretną przestrzeń

1. Otwórz Klyo → Zespół → Pliki → Configure SharePoint jako właściciel zespołu. W Prywatne konfigurujesz oddzielne połączenie widoczne tylko dla siebie.

2. Kliknij Connect Microsoft, zaloguj się i zaakceptuj wymagane uprawnienia.

3. Wyszukaj witrynę, wybierz bibliotekę dokumentów i folder. Zalecany jest osobny folder, np. Klyo CRM.

4. Kliknij Użyj tego folderu na pliki CRM.

5. Wgraj próbny plik, otwórz go, a następnie podłącz dokument do kontaktu albo oferty.

Członkowie zespołu mogą dodawać i podłączać pliki; użytkownicy z rolą Viewer mogą je przeglądać. Wyłącznie właściciel zespołu może zmienić połączenie i folder. Link do dokumentu otwierany w Microsoft nadal podlega uprawnieniom Microsoft 365 — członkowie zespołu powinni mieć dostęp do wybranej biblioteki. SharePoint w CRM jest współdzielony z zespołem poprzez konto podłączone przez właściciela; wybierz folder przeznaczony do wspólnej pracy.

Co obsługuje integracja

- Ręczne wgrywanie plików do 250 MB, porcjami, ze wskazaniem postępu i ponowieniem nieudanego fragmentu.

- Podłączanie istniejących plików z wybranego folderu i jego podfolderów.

- Powiązanie pliku z kontaktem, firmą, transakcją, produktem lub ofertą.

- Import cenników CSV/XLSX do 10 MB bezpośrednio z SharePoint, z podglądem i zatwierdzeniem.

- Oddzielne połączenia i listy dokumentów dla Team i Personal.

- Odłącz usuwa powiązanie w Klyo, zachowując plik w SharePoint. Odłącz zachowuje pliki i ich metadane, ale blokuje dostęp z CRM do ponownego połączenia właściwego folderu.

Po przekazaniu własności zespołu połączenie jest odłączane; nowy właściciel łączy swoje konto Microsoft i wybiera folder. Pliki pozostają w SharePoint. Nowe pliki otrzymują krótki losowy dopisek w nazwie, aby nie nadpisywać istniejących dokumentów.

Zmiana folderu przerywa rozpoczęte wgrywanie. Po zamknięciu okna wgrywania transfer zatrzymuje się po bieżącym fragmencie; nie jest wznawiany po przeładowaniu strony. Niedokończone sesje wygasają po stronie Microsoft. Rozmiary i dostępność nadal zależą od ograniczeń biblioteki oraz konta Microsoft 365. Integracja nie synchronizuje plików w tle i nie tworzy automatycznych wiadomości.

Problemy

- Microsoft sign-in has not been configured — sprawdź MICROSOFT_CLIENT_ID i MICROSOFT_CLIENT_SECRET, a następnie wdrożenie Railway.

- Redirect URI mismatch — adres Web w Entra musi być identyczny z MICROSOFT_REDIRECT_URI, łącznie z HTTPS i ścieżką.

- Need admin approval / brak witryn — administrator Microsoft musi zatwierdzić uprawnienia i zapewnić kontu dostęp do witryny.

- Reconnect your Microsoft account — połączenie wygasło albo uprawnienia zostały cofnięte. Wybierz Reconnect Microsoft i ponownie wskaż folder.

- This item is outside the connected CRM folder — wybierz dokument we wskazanym folderze lub jego podfolderze.

Dokumentacja Microsoft: rejestracja aplikacji, logowanie z kodem autoryzacyjnym, sesje wgrywania, wyszukiwanie witryn.
