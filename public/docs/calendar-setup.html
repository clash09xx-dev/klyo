Calendar integrations

In Calendar → Connect calendars, each user connects Google Calendar, Outlook / Microsoft 365 or iCloud, chooses a calendar, and sees its events beside CRM events. Connections are private to that user in the active Team or Personal space. Personal and Team have separate connections. A connected account is never automatically shared with colleagues.

Google Calendar

Use the existing Google OAuth web application (the same GOOGLE_CLIENT_ID and GOOGLE_CLIENT_SECRET used by Klyo). Enable Google Calendar API in Google Cloud. Keep all existing login/Gmail/Drive callback URLs and add this authorized Web redirect URI:

https://klyolabs.com/api/calendar-integrations/oauth/google/callback

The integration requests openid and email, plus calendar.calendarlist.readonly and calendar.events under https://www.googleapis.com/auth/. These permissions allow choosing accessible calendars and reading/writing their events. Google may require OAuth app verification for production use. In testing mode add the intended Google accounts as test users; Google's test-mode refresh-token limits still apply. Reconnect if consent expires.

Set GOOGLE_CLIENT_ID and GOOGLE_CLIENT_SECRET in Railway. Set APP_URL=https://klyolabs.com. Do not expose client secrets in browser code or paste them into chat. Then open Calendar → Connect calendars → Google Calendar → Connect, sign in, review consent and choose a calendar. Read-only calendars can be displayed; publishing requires a writable calendar.

Outlook / Microsoft 365

Use the existing Microsoft Entra application, preserving its SharePoint and inbox redirect URIs. Add this Web redirect URI:

https://klyolabs.com/api/calendar-integrations/oauth/microsoft/callback

Add the Microsoft Graph delegated permission Calendars.ReadWrite. Offline access enables token renewal. Organization policy may require administrator consent. No application-wide calendar permissions or mail-sending permissions are required by this integration.

Set MICROSOFT_CLIENT_ID and MICROSOFT_CLIENT_SECRET in Railway. The calendar authority uses CALENDAR_MICROSOFT_TENANT_ID when set, otherwise MICROSOFT_TENANT_ID, otherwise common. Use organizations or your tenant UUID for work accounts. For personal Outlook.com accounts the Entra application's supported account types must include personal Microsoft accounts, and calendar authority must use common or consumers. This calendar-specific setting does not change the existing SharePoint authority.

Connect from Calendar → Connect calendars → Outlook / Microsoft 365, then choose an accessible calendar. The integration uses the signed-in account's calendars, not arbitrary delegated mailboxes. Calendar policies and permissions still apply.

Google / Microsoft: how events move

  • Refresh reads the selected provider calendars for the displayed month. Repeated reads do not create CRM records. Recurring events are displayed as instances returned by the provider. All-day end dates are exclusive; times are displayed in the user's local timezone.
  • External events have a provider marker and are private. Open one and choose Copy to Team CRM or Copy to Personal CRM to copy its title, dates, location and description. Team copying explicitly makes those details visible to colleagues. Repeated copying reuses the existing CRM event.
  • Create or edit a CRM event and Save first. Open it again → Google / Outlook → Send to. Klyo publishes an appointment without attendees. Existing CRM events are not bulk-published, and imported meetings are not silently changed.
  • A link exposes Publish CRM version and Pull calendar version. These are explicit actions, not automatic two-way writes. Publishing refuses to overwrite a provider event changed since the last synchronization. Pulling replaces the CRM title, dates, description and location, while retaining CRM contact/deal links. A stale CRM revision requires reloading before either action.
  • Provider meetings with attendees or recurring event series must be managed in Google or Outlook. Klyo does not send attendee invitations. Copied external meetings are read-only toward their original provider; use Pull to refresh their CRM copy.
  • Unlink, deleting a CRM event, switching calendars or disconnecting the account does not delete events from the provider. Disconnecting removes Klyo's saved credentials and links; independent CRM copies remain. Reconnecting is a new link context, so review existing external appointments before publishing again.
  • Failed initial publication keeps the operation ID and original payload. Retrying the same link uses a stable Google event ID or Microsoft transaction ID to avoid duplicate creation. If CRM data changed during a failed attempt, the link indicates unpublished CRM changes after recovery. Do not unlink a pending operation just to retry it.

Google/Microsoft remain the authority for their own recurring meetings, reminders, attendees and conferencing. This release does not create Google Meet/Teams conferences, manage attendee responses or run background outbound workflows.

Apple Calendar / iCloud — two-way synchronization

Open Settings → Integrations → Apple Calendar / iCloud → Connect. Enter your Apple ID email and an app-specific password, then choose a calendar. You do not need operator Apple API keys. In Apple Account, go to Sign-In and Security → App-Specific Passwords → Generate. Apple requires two-factor authentication. Never enter your main Apple Account password in Klyo.

Your selected calendar is private. Use Copy to CRM or Send to iCloud to link selected appointments. Enable Automatic two-way sync after reviewing the confirmation: updates and deletions of linked events then propagate both ways, checked approximately every two minutes. Sync now checks immediately. In Team, colleagues' edits to linked shared events also reach your iCloud. Other private appointments are never bulk-imported.

Simultaneous changes are flagged for review instead of silently overwritten. Use the event's calendar links to review and pull a version. Recurring series and invitations remain editable in Apple Calendar; Klyo displays their occurrences and retains original recurrence, attendee and alarm data. Some moved or removed occurrences require review in Apple Calendar.

Pause automatic sync, Unlink or Disconnect stops automatic synchronization and keeps independent events. Changing calendar pauses sync. Credentials are encrypted per user and Team/Personal space. Revoke the app-specific password in Apple Account to remove access; use Update password to reconnect, reselect the calendar and re-enable sync.

Export CRM .ics remains available as a separate offline file export for compatible calendar apps. Repeated file imports may create duplicates.

Secrets and testing

Use the stable server-only INTEGRATION_ENCRYPTION_KEY already configured for Klyo integrations. Calendar credentials are encrypted in PostgreSQL; status endpoints never return tokens. Rotating the encryption secret requires reconnecting accounts. Do not connect a private calendar if you are not authorized to copy its data into the team's CRM.

Provider adapters and user workflows are tested against simulated provider responses and an isolated database. Actual OAuth acceptance, tenant consent and account-specific calendar access require the owner's configured Google/Microsoft application and real account authorization. A missing configuration appears as unavailable in the connection dialog, not as a successful connection.

Integracje kalendarzy

W Kalendarz → Połącz kalendarze każdy użytkownik łączy Google Calendar albo Outlook / Microsoft 365, wybiera kalendarz i ogląda jego wydarzenia obok wydarzeń CRM. Połączenie jest prywatne dla tej osoby w aktywnej przestrzeni zespołowej lub prywatnej. Obie przestrzenie mają oddzielne połączenia. Konto nie jest automatycznie udostępniane współpracownikom.

Google Calendar

Użyj istniejącej aplikacji internetowej OAuth Google i tych samych GOOGLE_CLIENT_ID oraz GOOGLE_CLIENT_SECRET. Włącz Google Calendar API w Google Cloud. Zachowaj adresy powrotne logowania, Gmaila i Drive, a następnie dodaj autoryzowany adres przekierowania aplikacji internetowej:

https://klyolabs.com/api/calendar-integrations/oauth/google/callback

Integracja prosi o openid, email, https://www.googleapis.com/auth/calendar.calendarlist.readonly i https://www.googleapis.com/auth/calendar.events. Pozwalają one wybrać dostępny kalendarz oraz czytać i zapisywać jego wydarzenia. Google może wymagać weryfikacji OAuth przed użyciem produkcyjnym. W trybie testowym dodaj właściwe konta do użytkowników testowych; nadal obowiązują limity ważności tokenów testowych. Po wygaśnięciu zgody połącz konto ponownie.

W Railway ustaw GOOGLE_CLIENT_ID, GOOGLE_CLIENT_SECRET i APP_URL=https://klyolabs.com. Nie umieszczaj sekretów w przeglądarce i nie przesyłaj ich przez czat. Otwórz Kalendarz → Połącz kalendarze → Google Calendar → Połącz, zaloguj się, sprawdź zgodę i wybierz kalendarz. Kalendarze tylko do odczytu można wyświetlać; publikowanie wymaga prawa zapisu.

Outlook / Microsoft 365

Użyj istniejącej aplikacji Microsoft Entra. Zachowaj adresy SharePoint i skrzynki odbiorczej i dodaj adres przekierowania typu Web:

https://klyolabs.com/api/calendar-integrations/oauth/microsoft/callback

Dodaj delegowane uprawnienie Microsoft Graph Calendars.ReadWrite. Dostęp offline pozwala odświeżać tokeny. Polityka organizacji może wymagać zgody administratora. Nie są potrzebne uprawnienia aplikacyjne do wszystkich kalendarzy ani uprawnienia wysyłki poczty.

W Railway ustaw MICROSOFT_CLIENT_ID i MICROSOFT_CLIENT_SECRET. Kalendarz używa CALENDAR_MICROSOFT_TENANT_ID, jeśli istnieje; w przeciwnym razie MICROSOFT_TENANT_ID, a na końcu common. Dla kont firmowych użyj organizations lub UUID dzierżawy. Dla prywatnych kont Outlook.com rejestracja Entra musi dopuszczać konta osobiste, a ustawienie kalendarza musi mieć common albo consumers. To ustawienie nie zmienia konfiguracji SharePoint.

Połącz przez Kalendarz → Połącz kalendarze → Outlook / Microsoft 365 i wybierz dostępny kalendarz. Integracja korzysta z kalendarzy zalogowanej osoby, a nie dowolnych delegowanych skrzynek. Nadal obowiązują uprawnienia i polityki dostawcy.

Google / Microsoft: przenoszenie wydarzeń

  • Odśwież odczytuje wybrane kalendarze dla widocznego miesiąca. Kolejne odczyty nie tworzą rekordów CRM. Wydarzenia cykliczne są pokazywane jako wystąpienia zwrócone przez dostawcę. Końcowa data całodniowego wydarzenia nie jest wliczana; godziny są w lokalnej strefie użytkownika.
  • Wydarzenia zewnętrzne mają oznaczenie dostawcy i są prywatne. Otwórz wydarzenie i wybierz Kopiuj do CRM zespołu lub Kopiuj do prywatnego CRM, aby skopiować tytuł, daty, lokalizację i opis. Kopiowanie do zespołu jawnie udostępnia te dane współpracownikom. Powtórzenie używa istniejącej kopii.
  • Utwórz lub edytuj wydarzenie CRM i najpierw je Zapisz. Otwórz ponownie → Google / Outlook → Wyślij do. Klyo publikuje termin bez uczestników. Nie publikuje masowo istniejących wydarzeń i nie zmienia po cichu zaimportowanych spotkań.
  • Powiązanie udostępnia Opublikuj wersję CRM oraz Pobierz wersję kalendarza. To jawne operacje, a nie automatyczny zapis w obie strony. Publikacja odmawia nadpisania wydarzenia zmienionego u dostawcy od ostatniej synchronizacji. Pobranie zastępuje tytuł, daty, opis i lokalizację CRM, zachowując powiązania z kontaktami i szansami. Nieaktualną wersję CRM trzeba wcześniej odświeżyć.
  • Spotkania z uczestnikami i całe serie cykliczne obsługuj w Google lub Outlooku. Klyo nie wysyła zaproszeń. Kopie spotkań zewnętrznych nie mogą zmieniać oryginału u dostawcy; użyj Pobierz, aby odświeżyć kopię CRM.
  • Odłącz powiązanie, usunięcie wydarzenia CRM, zmiana kalendarza lub odłączenie konta nie usuwa wydarzeń u dostawcy. Wydarzenia CRM pozostają, a mapowania połączenia mogą zostać usunięte.

Apple Calendar / iCloud — synchronizacja w obie strony

Otwórz Ustawienia → Integracje → Apple Calendar / iCloud → Połącz. Wpisz email Apple ID i hasło aplikacji, następnie wybierz kalendarz. Operator Klyo nie potrzebuje kluczy API Apple. Na koncie Apple wybierz Logowanie i zabezpieczenia → Hasła aplikacji → Wygeneruj. Apple wymaga uwierzytelniania dwupoziomowego. Nigdy nie podawaj w Klyo głównego hasła konta Apple.

Wybrany kalendarz pozostaje prywatny. Wybierz Kopiuj do CRM lub Wyślij do iCloud, aby powiązać konkretne terminy. Po potwierdzeniu włącz Automatyczną synchronizację w obie strony: zmiany i usunięcia powiązanych wydarzeń będą przenoszone w obu kierunkach, z kontrolą mniej więcej co dwie minuty. Synchronizuj teraz uruchamia kontrolę od razu. W Team zmiany współpracowników w powiązanych wydarzeniach również trafią do Twojego iCloud. Pozostałe prywatne terminy nie są masowo importowane.

Równoczesne zmiany wymagają Twojej decyzji. Otwórz połączenia wydarzenia i sprawdź wersję Apple przed jej pobraniem. Serie cykliczne i zaproszenia edytujesz w Apple Calendar; Klyo pokazuje ich wystąpienia, zachowując dane cyklu, uczestników i alarmów. Niektóre przeniesione lub usunięte wystąpienia wymagają sprawdzenia w Apple Calendar.

Wstrzymaj synchronizację, Odłącz powiązanie lub Odłącz konto zatrzymuje automatyczne zmiany i zachowuje niezależne wydarzenia. Zmiana wybranego kalendarza wstrzymuje synchronizację. Dane dostępu są szyfrowane osobno dla użytkownika i przestrzeni Team/Personal. Cofnij hasło aplikacji na koncie Apple, aby odebrać dostęp; w Klyo użyj Zmień hasło aplikacji, wybierz ponownie kalendarz i włącz synchronizację.

Eksport CRM .ics pozostaje osobną opcją eksportu pliku do innych programów. Wielokrotny import pliku może tworzyć duplikaty.

Bezpieczeństwo i ograniczenia

Połączenia są przypisane do użytkownika i aktywnej przestrzeni, tokeny są szyfrowane, a zgody OAuth sprawdzają krótko ważny stan i PKCE. Odłączenie nie usuwa kopii wydarzeń CRM ani wydarzeń Google lub Outlook. Działanie zależy od uprawnień, limitów API i dostępności dostawcy. Przy błędzie integracja pokazuje komunikat zamiast pozorować udane połączenie. Przetestuj rzeczywiste konto; automatyczne testy Klyo używają symulowanych dostawców.
